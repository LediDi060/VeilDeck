# VeilDeck

Учебный демонстрационный MVP «Confidential Teaser & Controlled Disclosure» (кейс B, партнёр Smart IMMO Invest). Проектный практикум магистратуры «Программная инженерия безопасных систем» (УрФУ × Нетология).

Система публикует **обезличенные карточки** корпоративных возможностей (teaser), по которым нельзя определить организацию. Расширенные сведения и документы раскрываются конкретному внешнему пользователю **только после ручного одобрения**, на ограниченный срок, с немедленным отзывом доступа и полным аудитом. Почта и публичные облачные ссылки этого не обеспечивают.

> Только демонстрация в изолированной среде, только синтетические данные. Не production.

## Статус

Реализован первый срез PostgreSQL + публичный REST-каталог: миграции, две таблицы, безопасная teaser-проекция,
лимитер и синтетические карточки. Запуск и примеры запросов — [docs/database-rest.md](docs/database-rest.md).
Остальные возможности ниже описывают целевой MVP. План — `openspec/changes/add-controlled-disclosure-mvp/tasks.md`.
Сдача — начало ноября 2026, защита — начало декабря 2026.

## Роли

| Роль | Кто | Аутентификация |
|---|---|---|
| anonymous | любой посетитель | нет |
| requester | отправил запрос на доступ | нет, ответ приходит на e-mail |
| viewer | requester с одобренным доступом | одноразовая ссылка → сессия, привязанная к доступу |
| reviewer | сотрудник SMI | пароль + TOTP |
| admin | администратор | пароль + TOTP |

## Функциональные возможности

1. **Каталог teaser-карточек** — публичный список и карточка только с обезличенными полями (отрасль, макрорегион, диапазоны размера и выручки, тип сделки), фильтры, пагинация, rate limit. Черновик, архивная и несуществующая карточки неразличимы (404).
2. **Запросы доступа** — форма с согласием, honeypot, лимиты по IP и e-mail. Ответ всегда одинаковый (202), существование запроса не раскрывается. E-mail хранится зашифрованным.
3. **Решения reviewer** — очередь запросов, одобрение (выбор материалов, срок до 168 ч, лимит просмотров, запрет скачивания по умолчанию) или отказ с причиной. Решение единственное, автоодобрения нет. Отзыв, сокращение срока, перевыпуск ссылки.
4. **Доступ viewer** — одноразовая ссылка на 30 минут, токен во fragment (не попадает в логи и Referer), серверная сессия с idle-таймаутом, мгновенный отзыв.
5. **Защищённый контент** — страницы PDF отдаются растром с серверным watermark и HMAC-кодом для поиска источника утечки; оригиналы не отдаются; счётчик просмотров; скачивание watermarked-копии только по разрешению.
6. **Staff-аутентификация и RBAC** — пароль (argon2id) + TOTP, блокировка после неудачных попыток, deny-by-default, разделение обязанностей: admin не одобряет запросы, reviewer не публикует карточки.
7. **Управление карточками** — CRUD, draft/publish/archive, линтер утечек (название организации, e-mail, телефон, ИНН и т. п. в teaser блокируют публикацию), предупреждение об уникальной комбинации признаков, безопасная загрузка материалов.
8. **Аудит** — журнал только на добавление (права БД, триггер, hash-цепочка), просмотр с фильтрами, CSV-экспорт, проверка целостности, поиск источника утечки по watermark-коду.
9. **Retention** — автоматическое истечение доступов и обезличивание запросов по срокам, ручное удаление материалов и запросов.
10. **Платформенная безопасность** — заголовки (HSTS, строгий CSP), CSRF, rate limiting, единый формат ошибок, секреты из окружения, защищённый Compose, CI с проверками безопасности.

Ключевой сценарий демо: каталог → запрос → одобрение → письмо в Mailpit → просмотр с watermark → повторное использование ссылки (отказ) → попытка IDOR → отзыв → аудит и trace watermark → CI блокирует секрет.

## Что вне scope

Платежи, ЮЗЭДО, автоматические решения с правовыми последствиями, постоянные кабинеты внешних пользователей, регистрация и соцлогин, реальная почта/SMS, реальные документы и ПДн, Kubernetes, DRM, WAF, HSM, шифрованные бэкапы, мониторинг.

Остаточный риск: запрет скачивания не защищает от скриншота или записи экрана — для этого и нужен watermark.

## Архитектура

```
Браузер ──HTTPS──▶ nginx ──▶ API (FastAPI) ──▶ PostgreSQL
                   │  └─ SPA     │  └────────▶ Redis (сессии, rate limit)
                   │             └───────────▶ Mailpit
                   └ worker (retention)
```

- **Backend:** Python 3.12, FastAPI, SQLAlchemy 2, Alembic, Pydantic v2.
- **Frontend:** React 19, TypeScript, Vite, antd 6, zustand, архитектура FSD.
- **Данные:** PostgreSQL 16, Redis 7; сессии на сервере, без JWT.
- **Инфраструктура:** nginx как единственная точка входа, Mailpit, Docker Compose.

Подробно: `openspec/changes/add-controlled-disclosure-mvp/design.md` (trust boundaries, модель данных, матрица доступа, threat model STRIDE на 20 угроз, 33 security-требования, маппинг на ASVS 5.0, retention-матрица).
